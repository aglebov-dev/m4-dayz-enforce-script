# Дерево типов

[← К оглавлению](../../README.ru.md) · [English version](../en/03-type-explorer.md)

Иконка **M4** на панели слева открывает дерево всего, что расширение знает о проекте. Дерево
повторяет диск и ленивое — корпус в 8000 классов открывается мгновенно.

```
@MyMod                       ← корень решения, имя из build.modName
  Properties                 ← манифест
  Run and debug              ← свёрнут по умолчанию, см. 05-debugging.md
  Dependencies  5 entries    ← движок и каждая запись load[]
  MyMod  project             ← ваши исходники, папка в папку
```

- Папка с `config.cpp` рисуется модом; сам `config.cpp` раскрывается классами `CfgPatches` /
  `CfgMods`, а его `#define` становятся узлами со значениями (иначе `*_Preload`-аддоны выглядят
  пустыми).
- Read-only помечено замком.
- Нет `enforce.project.json` — панель предложит его создать. Не нашлись скрипты движка —
  появится строка **engine — not set** с кнопкой выбора папки.

## Тулбар

| Кнопка | Что делает |
| --- | --- |
| Search Types | Фильтр дерева по имени; кнопка превращается в Clear Search |
| Filter Symbol Kinds | Оставить только классы, методы, поля, enum… |
| Refresh Types | Перечитать дерево |
| Show Current File in Type Explorer | Показать файл активного редактора |
| Collapse All / Expand Project | Свернуть всё / раскрыть свои моды |
| Only Scripts | Срезать дерево до кода, скрыв не-скриптовые файлы |

**Show in Type Explorer** в контекстном меню редактора показывает в дереве определение под
курсором.

## Зависимости

Подключаются из дерева, а не руками. В контекстном меню узла `Dependencies` два пункта —
режим диалога у них разный, потому что системный диалог Windows не умеет предлагать файлы
и папки одновременно:

- **Add Mod Folder…** — папка с `config.cpp` внутри (`@Mod` или его `addons`);
- **Add Single PBO…** — один запакованный аддон, распакуется в кэш;
- **−** на записи убирает её из манифеста — на диске ничего не трогается, комментарии в
  манифесте переживают правку.

Зависимость из одних конфигов (без единого `.c`) подключается так же и индексируется
полностью.

Рядом с манифестом расширение ведёт `enforce.deps.json`: хеш каждого pbo и папка распаковки,
чтобы «тот ли это мод» был вопросом с ответом. Запакованные моды распаковываются в кэш
расширения (только скрипты и конфиги; бинаризованные конфиги разворачиваются в текст) и
обновляются, когда мод обновился на диске.

Кэш — зеркало PBO, а не рабочая копия: правки в нём стираются. Нужно менять код зависимости —
распакуйте PBO сами и подключите папку как исходники.

Обфусцированные моды открываются в режиме *API-only*: объявления без тел. API может извлечься
частично или не извлечься вовсе; в карту путей отладчика такие моды не попадают
(см. [Отладка](05-debugging.md#ограничения)).

Моды, упакованные токенным `#ifdef`-супом, пропускаются: ни API, ни тел от них нет.

## Файловые операции

По умолчанию дерево — просмотрщик: в контекстном меню копирование путей и «показать в
проводнике». Настройка `enforce.explorerEdit` = `true` добавляет файловые операции:

`New Mod…`, `Add Existing Mod…`, `New Folder…`, `New Script…`, `New config.cpp`, `Rename…`,
`Delete`.

Они появляются только на ваших исходниках — движок и зависимости остаются read-only.

## Команды

| Команда | Описание |
| --- | --- |
| `Enforce: Search Types` / `Clear Search` | Фильтр дерева по имени |
| `Enforce: Filter Symbol Kinds` | Ограничить дерево видами символов |
| `Enforce: Only Scripts` | Показывать только код |
| `Enforce: Refresh Types` / `Collapse All` / `Expand Project` | Управление деревом |
| `Enforce: Show Current File in Type Explorer` / `Show in Type Explorer` | Показать файл или определение |
| `Enforce: Add Dependency…` / `Remove Dependency` | Правка `load[]` из дерева |
| `Enforce: Set Engine Scripts Folder…` | Указать папку скриптов движка |
| `Enforce: Create Project File` | Создать `enforce.project.json` |
