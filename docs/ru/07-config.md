# Работа с config.cpp

[← К оглавлению](../../README.ru.md) · [English version](../en/07-config.md)

Конфиги индексируются отдельно от скриптов: проект, зависимости из `load[]` и данные
движка (`DZ` рядом со `scripts`). Индекс строится при первом обращении к `config.cpp`;
после сохранения перечитывается только сохранённый файл.

Конфиг — одно дерево, склеенное из всех загруженных аддонов, поэтому классы адресуются
ПОЛНЫМ ПУТЁМ: одно и то же имя в `CfgPatches`, `CfgMods` и `CfgVehicles` — три разных
класса.

## Что поддержано

| Возможность | Где |
| --- | --- |
| Автодополнение | классы, аддоны в `requiredAddons[]`, свойства по цепочке наследования |
| Наведение | классы, аддоны, свойства |
| `F12` | база класса, `class X;`, строка-имя класса, аддон, перекрытое свойство |
| `Shift+F12` | панель **Enforce References** — та же, что у скриптов |
| Диагностика | синтаксис, значения, наследование — таблица ниже |
| Быстрые правки | `Ctrl+.` на большинстве жалоб |
| Форматирование | `Shift+Alt+F`, длинные массивы разворачиваются по элементам |
| Подсветка | имя типа красится, только если он резолвится по корпусу |

## Диагностика

Все правила проверены на 785 конфигах ванили, Expansion и M4: ложных срабатываний нет.
Уровень выбран по последствию, а не по виду записи.

| Код | Уровень | Что ловит |
| --- | --- | --- |
| `required-addon-missing` | ошибка | зависимость из `requiredAddons[]` не подключена |
| `class-not-available` | ошибка | базы нет ни в проекте, ни в зависимостях, ни в движке |
| `base-not-declared` | ошибка | база из чужого аддона без `class X;` в этом файле |
| `self-base-class` | ошибка | `class X: X` на верхнем уровне |
| `array-without-brackets` | ошибка | `healthLevels = {…}` без `[]` у имени |
| `value-missing-semicolon` | ошибка | запись без `;` — значение забирает следующую строку |
| `string-not-closed`, `array-not-closed` | ошибка | незакрытая кавычка, незакрытый `{` |
| `brace-not-closed`, `stray-brace` | ошибка | баланс `{}` по файлу |
| `unquoted-expression` | ошибка | `x = 1 + 2;` без кавычек не вычисляется |
| `broken-expression` | ошибка | `"(0.4/4"` — вычислитель молча даёт 0 |
| `bool-literal` | предупреждение | `x = true;` хранится строкой, числовое чтение даёт 0 |
| `int-overflow` | предупреждение | целое вне 32 бит |
| `bad-number` | предупреждение | `0.6.1`, `12ab` — станет строкой |
| `value-shape-mismatch` | предупреждение | форма расходится с корпусом: «здесь строка, а в 133 из 134 записей число» |
| `unquoted-value` | подсказка | `scope = asdasd;` — значение без кавычек |
| `value-empty` | подсказка | `maxCargo = ;` |
| `array-empty-item` | подсказка | `{"a",,12}` — появится пустой элемент |
| `array-trailing-comma` | подсказка | `{1,2,}` — движок её игнорирует |
| `array-item-run-on` | предупреждение | `{12 "path"}` — между значениями потеряна запятая |

Что важно знать про значения (проверено зондами на живом сервере):

- **числа и строки взаимозаменяемы не всегда.** Движок и объектный геттер
  (`item.ConfigGetInt("weight")`) читают `"200g"` как 200 и вычисляют `"0.3926/4"`;
  глобальный `GetGame().ConfigGetInt(path)` на строке возвращает 0;
- **`int` и `float` неразличимы** — одно и то же `20` в ванили лежит то так, то этак;
- **`true`/`false` не булевы**: пишут `0`/`1`;
- отдельного типа «версия» нет — `0.6.1` станет строкой.

## Быстрые правки

`Ctrl+.` предлагает правку там, где она однозначна: заменить `true` на `1`, взять
значение в кавычки, поставить `;`, закрыть кавычку или скобку, дописать `[]`, объявить
базу (`class X;`), убрать `: X` у самого себя, убрать лишнюю запятую.

Где вариантов несколько — переполнение `int`, незакрытый блок, мусорное значение вроде
`"0..7"` — правки нет: подставить наугад хуже, чем оставить решение автору.

## Форматирование

`Shift+Alt+F`: отступы табами, `{` со своей строки, `};` в конце тела, пробелы вокруг `=`.
Значения не переписываются — правятся отступы, пробелы и переносы, поэтому форматтер
безопасен и на файле с ошибкой.

Длинные массивы разворачиваются по элементам, вложенные — рекурсивно:

```cpp
healthLevels[] =
{
	{
		1,
		{
			"data\jacket.rvmat",
			"data\knop.rvmat"
		}
	},
	…
};
```

Порог строки — `enforce.configFormatting.maxLineLength` (по умолчанию 120).

## Наведение

**Класс** — полный путь (каждое звено кликабельно), происхождение, цепочка баз:

```
class
● defines (1)   ● usages

CfgVehicles.TShirt_Black (engine)

inherits:
→ TShirt_ColorBase
→ Clothing
→ Clothing_Base
→ Inventory_Base
```

**Вложенный класс** — вместо цепочки баз показываются СЛОИ: одноимённые вложенные классы
у предков владельца. Оттуда и приезжают свойства, хотя ни одного `:` в тексте нет:

```
CfgVehicles.Animal_BosTaurus.DamageSystem (engine)
● defines (1)   ● layers (2)   ● usages

inherited from:
→ AnimalBase.DamageSystem
→ AllVehicles.DamageSystem
```

`class GlobalHealth: GlobalHealth` в ванили — не цикл, а «расширить унаследованный»:
имя справа резолвится в одноимённый вложенный класс предка.

**Свойство** — путь до самого свойства и что оно перекрывает, со значениями. Для `+=`
раздел называется `appends to:` — там дописывание к унаследованному массиву. Массивы
длиннее 100 знаков показываются заглушкой `{.....}`.

```
property
● defines (3)   ● usages

CfgVehicles.TShirt_Black.scope

overrides:
→ Clothing_Base.scope = 0
→ Inventory_Base.scope = 0
```

**Аддон** — происхождение и `requiredAddons[]` списком, каждая зависимость кликабельна.

## Панель ссылок

`Shift+F12` на классе, аддоне или свойстве открывает ту же панель, что и в скриптах.
Определения идут группой сверху, использования ниже. Колонка `File` — путь относительно
мода, `Mod` — сам мод: все конфиги зовутся `config.cpp`, иначе строки неотличимы.

Ссылки в попапе (`defines` / `layers` / `usages` / `all`) открывают панель с предфильтром.

## Автодополнение

- в теле класса — свойства всех предков, у каждой строки виден класс-источник;
  порядок от ближайшего предка к дальним, уже написанное в этом теле не предлагается;
  у вложенного класса (`Protection`, `DamageSystem`) свойства берутся ещё и у одноимённых
  классов корпуса — цепочка наследования владельца о них не знает;
- свойство-массив подставляется сразу с `[]`;
- после `:` — имена классов, в `requiredAddons[]` — имена аддонов, в том числе ВНЕ
  кавычек: кавычки дописываются при подстановке;
- **после `=` — значения, которые у этого свойства встречаются в корпусе**, с частотой
  в подписи (`scope` → `1` 9115×, `2` 3280×, `0` 361×). Показываются только словарные
  свойства — до 12 разных значений при заметной частоте; у `displayName` или `model`
  значения уникальны, там подсказок нет;
- внутри значения (`{…}`, после `=` в массиве) список не показывается вовсе;
- совпадением считается точное вхождение набранного текста.

## Чужие конфиги

Файлы движка и зависимостей открываются только для чтения (`enforce.readonlyExternal`),
в дереве помечены замком. Данные движка доступны как корень `engine data`.

## Чего пока нет

- проверка «подходит ли значение ЭТОМУ свойству» по смыслу: сравниваем только форму
  записи с корпусом, контракта у свойств в конфиге не существует;
- `#include` в конфигах не разворачивается;
- порядок загрузки из `load[]` в разбор конфигов не заведён: показываем, ЧТО перекрывает
  что по наследованию, но не утверждаем, какое значение победит между модами.
