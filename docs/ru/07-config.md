# Работа с config.cpp

[← К оглавлению](../../README.ru.md) · [English version](../en/07-config.md)

Конфиги индексируются отдельно от скриптов: проект, зависимости из `load[]` и данные
движка (`DZ` рядом со `scripts`). Индекс строится при первом обращении к `config.cpp`;
после сохранения перечитывается только сохранённый файл.

Конфиг — одно дерево, склеенное из всех загруженных аддонов, поэтому классы адресуются
ПОЛНЫМ ПУТЁМ: одно и то же имя в `CfgPatches`, `CfgMods` и `CfgVehicles` — три разных
класса.

## Что поддержано

| Возможность | Где |
| --- | --- |
| Автодополнение | классы, аддоны в `requiredAddons[]`, свойства по цепочке наследования |
| Наведение | классы, аддоны, свойства |
| `F12` | база класса, `class X;`, строка-имя класса, аддон, перекрытое свойство |
| `Shift+F12` | панель **Enforce References** — та же, что у скриптов |
| Диагностика | зависимость из `requiredAddons[]` не подключена; тип, которого нет ни в одной зависимости |

## Наведение

**Класс** — полный путь (каждое звено кликабельно), происхождение, цепочка баз:

```
class
● defines (1)   ● usages

CfgVehicles.TShirt_Black (engine)

inherits:
→ TShirt_ColorBase
→ Clothing
→ Clothing_Base
→ Inventory_Base
```

**Вложенный класс** — вместо цепочки баз показываются СЛОИ: одноимённые вложенные классы
у предков владельца. Оттуда и приезжают свойства, хотя ни одного `:` в тексте нет:

```
CfgVehicles.Animal_BosTaurus.DamageSystem (engine)
● defines (1)   ● layers (2)   ● usages

inherited from:
→ AnimalBase.DamageSystem
→ AllVehicles.DamageSystem
```

`class GlobalHealth: GlobalHealth` в ванили — не цикл, а «расширить унаследованный»:
имя справа резолвится в одноимённый вложенный класс предка.

**Свойство** — путь до самого свойства и что оно перекрывает, со значениями. Для `+=`
раздел называется `appends to:` — там дописывание к унаследованному массиву. Массивы
длиннее 100 знаков показываются заглушкой `{.....}`.

```
property
● defines (3)   ● usages

CfgVehicles.TShirt_Black.scope

overrides:
→ Clothing_Base.scope = 0
→ Inventory_Base.scope = 0
```

**Аддон** — происхождение и `requiredAddons[]` списком, каждая зависимость кликабельна.

## Панель ссылок

`Shift+F12` на классе, аддоне или свойстве открывает ту же панель, что и в скриптах.
Определения идут группой сверху, использования ниже. Колонка `File` — путь относительно
мода, `Mod` — сам мод: все конфиги зовутся `config.cpp`, иначе строки неотличимы.

Ссылки в попапе (`defines` / `layers` / `usages` / `all`) открывают панель с предфильтром.

## Автодополнение

- в теле класса — свойства всех предков, у каждой строки виден класс-источник;
  порядок от ближайшего предка к дальним, уже написанное в этом теле не предлагается;
- после `:` — имена классов, в `requiredAddons[]` — имена аддонов;
- совпадением считается точное вхождение набранного текста.

## Чужие конфиги

Файлы движка и зависимостей открываются только для чтения (`enforce.readonlyExternal`),
в дереве помечены замком. Данные движка доступны как корень `engine data`.

## Чего пока нет

- **валидации значений** — типы полей конфига и проверка того, что в них написано,
  будут позже;
- `#include` в конфигах не разворачивается;
- порядок загрузки из `load[]` в разбор конфигов не заведён: показываем, ЧТО перекрывает
  что по наследованию, но не утверждаем, какое значение победит между модами.
