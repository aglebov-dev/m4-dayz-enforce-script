# Сборка

[← К оглавлению](../../README.ru.md) · [English version](../en/04-build.md)

Две точки входа:

| Клавиша | Что происходит |
| --- | --- |
| `F5` | Собрать PBO, затем скомпилировать их headless-сервером DayZ и показать вердикт |
| `Ctrl+Shift+B` | Только собрать PBO (задача `enforce: build PBO`) |

Для `F5` нужна конфигурация запуска — см. [Манифест и launch.json](06-manifest.md#launchjson).

Только Windows: гейт запускает `DayZServer_x64.exe`. На других системах он честно скажет, что
сервер не найден, — анализатор продолжит работать.

## Упаковка

- Каждый модуль с `config.cpp` пакуется в свой PBO — без AddonBuilder и прочих тулов.
- Префикс PBO не настраивается: он берётся из `config.cpp` модуля — из того же источника, что и
  карта путей отладчика.
- В PBO идут только скрипты: движку этого достаточно для вердикта, упаковка ассетов появится
  позже (`build.assets` зарезервирован).
- Результат: `<outDir>/<modName>/addons/*.pbo`.

## Зависимости

Движку идёт тот же `load[]`, что индексирует анализатор, — второго списка нет:

- готовый мод (папка `@Mod` или `.pbo`) подставляется в `-mod=` как есть;
- исходники с `config.cpp` сначала собираются в `<outDir>/deps/@Имя`.

Один источник правды: «в редакторе зелено, а сборка падает» здесь просто неоткуда взяться.
`build.deps` и `build.mods` удалены — игнорируются с предупреждением.

## Вердикт

- Первопричины отделены от каскада, который за ними тянется.
- Каждая ошибка замаплена обратно на ваш файл и попадает в Problems.
- Пути в логе Output кликабельны, включая ошибки внутри зависимостей.
- Модальные окна движка (`Addon 'X' requires addon 'Y'` и подобные) закрываются автоматически, а
  текст уходит в Output: сборка не ждёт, пока кто-то нажмёт OK.
- Логи прошлых прогонов, лежащие в той же папке профилей, отсекаются по времени.
- Если сервер выключился сам, прогон падает сразу, а не досиживает `build.timeoutSec`.
- После прогона реальный список дефайнов движка предлагается импортировать в манифест — только
  то, чего не видно из исходников.

После неудачи сервер ещё умирает в фоне; следующий `F5` дожидается его и повторяет запись PBO,
если файл всё ещё заблокирован.

Проверяются все файлы проекта, включая первый и последний, и проект из одного файла.
Вердикт снимается после конца компиляции, а не по первой строке о модуле; прогон, который
не удалось довести до конца, помечается как непроверенный.

## Что расширение запускает на вашей машине

Сам анализатор не запускает ничего: индекс, автокомплит, навигация, диагностика и предполёт —
это вычисления внутри процесса расширения. Процессы появляются, только когда вы просите сборку
или отладку, и их ровно три:

| Процесс | Когда | Зачем |
| --- | --- | --- |
| `DayZServer_x64.exe` (или `DayZDiag_x64.exe`) | `F5` | Компилирует собранный мод и даёт настоящий вердикт движка |
| `DayZDiag_x64.exe` | **Run server** / **Run client** | Сессия отладки, см. [05 · Отладка](05-debugging.md) |
| `powershell.exe` | во время сборки движком, только Windows | Закрывает модальные окна движка — подробности ниже |

### Зачем нужен вызов PowerShell

Когда движку не хватает аддона, он не падает — он открывает модальное окно `MessageBox` и ждёт
щелчка. На живом прогоне это остановило сборку на 19 секунд, а без человека у экрана сборка
умирает по детектору зависания и не сообщает настоящую причину. Вердикт, который зависит от
того, сидит ли кто-то рядом, — не вердикт.

Поэтому на время сборки движком расширение запускает один PowerShell-хелпер. Он обращается к
`user32.dll` через P/Invoke — иначе окно не увидеть, не втащив нативный модуль или новую
зависимость. Что он делает, и ничего кроме:

1. перечисляет окна верхнего уровня и оставляет те, что принадлежат **PID, который расширение
   запустило само** — чужие процессы не осматриваются никогда;
2. из них оставляет только окна класса `#32770` (стандартный диалог Windows), у которых есть и
   текст, и кнопка: движок создаёт и пустые служебные окна того же класса, а их закрытие срывает
   запуск;
3. копирует текст диалога в Output сборки, чтобы причина дошла до вас;
4. отправляет `BM_CLICK` первой кнопке, то есть нажимает **OK**;
5. завершается вместе со сборкой.

Скрипт кладётся во временный `.ps1` и запускается через `-File` — его можно прочитать прямо во
время работы; закодированной командой он не передаётся. Ни сети, ни записи куда-либо, кроме
временного файла и вашей папки сборки; после сборки ничего не остаётся.

## Уровни логирования

`enforce.build.logLevel` — что из лога движка попадает в канал сборки.

| Значение | Что остаётся в канале |
| --- | --- |
| `errors` | только ошибки |
| `important` (по умолчанию) | ошибки, предупреждения и вехи — `Module: …`, загрузка миссии, отсчёт выключения |
| `full` | всё, включая сырой хвост RPT, который печатается, когда сервер выключился сам |

`enforce.run.logLevel` — то же самое для отладочного запуска, см.
[05 · Отладка](05-debugging.md#логи).

## Предполёт

С включённым предполётом встроенный анализатор проходит по всему проекту **до** запуска
движка — чтобы не тратить круг через сервер на опечатку.

```jsonc
{ "engine": "P:/scripts", "build": { "preflight": true } }
```

- Останавливает только на том, что движок не примет: ошибки разбора, арность вызова,
  необъявленные символы.
- В диалоге всегда есть **Build anyway**.
- Находки помечены `[pre-flight]` и живут в Problems до следующего прогона. Правка файла снимает
  их по этому файлу; правка манифеста — нет: изменение `defines` переворачивает вердикт целиком,
  нужен новый прогон.
- `build.preflight` в манифесте перекрывает настройку `enforce.preflight`.

Предполёт не так полон, как вердикт настоящего компилятора, но это способ работать без
установленного DayZ Server: `F5` проверит проект, покажет ошибки и честно упрётся в
отсутствующий сервер.

## Где стоит сервер

```jsonc
"build": {
  "serverExe": "D:/Steam/steamapps/common/DayZServer/DayZServer_x64.exe",
  "serverCwd": "D:/Steam/steamapps/common/DayZServer",
  "serverCfg": "serverDZ.cfg",
  "mission": "mpmissions/dayzOffline.chernarusplus",
  "port": 2402,
  "profilesDir": "./builds/profiles",
  "timeoutSec": 240
}
```

Уберите `serverExe` и `serverCwd` — сервер найдётся сам по путям Steam. Без `port` берётся
случайный из 2416..2465, чтобы зависший сервер не блокировал прогон. `DayZDiag_x64.exe` в роли
гейта тоже работает, но ему нужен запущенный клиент Steam.

Полный справочник ключей — [Манифест и launch.json](06-manifest.md).
