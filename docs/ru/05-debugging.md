# Отладка

[← К оглавлению](../../README.ru.md) · [English version](../en/05-debugging.md)

Точки останова, стек вызовов, переменные, watch и debug-консоль для Enforce Script — из VS Code.

Отладка работает **только на `DayZDiag_x64.exe`**: в релизных сборках скрипт-отладчика нет
вообще. Только Windows.

## Как устроено

```
VS Code ──DAP── адаптер расширения ──TCP 1000/1001── DayZDiag_x64.exe
```

Игра подключается к отладчику **сама**; роль задаёт порт, ключей командной строки для этого не
нужно:

| Порт | Сторона |
| --- | --- |
| 1000 | клиент |
| 1001 | сервер |
| 1002 | второй клиент |

Сессия одновременно только одна — на двух движок виснет. Если порт занят, его обычно держит
Workbench Script Editor.

## Запуск

Дерево типов → секция **Run and debug** (под `Properties`):

| Строка | Что делает |
| --- | --- |
| `Listen for DayZDiag` | Держит порт выбранной стороны (`client` / `server` / `off`). Когда игра подключится, сессия отладки поднимется сама — нажимать ничего не нужно. |
| `Run server` | Запускает диаг сервером с отладочной копией конфига |
| `Run client` | Запускает диаг клиентом и подключает его к этому серверу |

Запущенный процесс гасится той же кнопкой. Те же действия есть в палитре:
**Enforce: Listen for DayZDiag**, **Enforce: Run Server**, **Enforce: Run Client**,
**Enforce: Stop Game and Debugging**.

Рабочий порядок: включить слушателя на нужную сторону → запустить эту сторону → при
необходимости поднять вторую. Диаг-клиент к релизному серверу не подключится (`0x00020017`) —
сервер поднимайте тем же диагом.

Чтобы подключиться к игре, запущенной руками, есть attach-конфигурация в `launch.json` — см.
[Манифест и launch.json](06-manifest.md#launchjson).

### Запуск по F5

Конфигурация `launch` делает то же, что кнопки: занимает порт, затем запускает сторону.

| Параметр | Значения | Что делает |
| --- | --- | --- |
| `listen` | `server` (порт 1001), `client` (порт 1000), `off` | Занимает порт до старта игры |
| `run` | `server`, `client`, `none` | Собирает PBO и запускает сторону |

```jsonc
{
  "type": "enforce",
  "request": "launch",
  "name": "Enforce: Run Server (debug)",
  "listen": "server",
  "run": "server"
}
```

Сессия отладки поднимется сама, когда игра подключится. Без `listen` и `run` конфигурация
`launch` — обычная сборка с проверкой.

## Настройка

Все ключи необязательные: диаг ищется в стандартных папках Steam, `serverDZ.cfg` — рядом с
сервером, миссия — из `build.mission`.

```jsonc
"debug": {
  "diagExe":      "D:/Steam/steamapps/common/DayZ/DayZDiag_x64.exe",
  "serverConfig": "D:/Steam/steamapps/common/DayZServer/serverDZ.cfg",
  "mission":      "mpmissions/dayzOffline.chernarusplus",
  "port":         2302,
  "playerName":   "dev"
}
```

| Ключ | Замечания |
| --- | --- |
| `diagExe` | Берите из папки **клиента**. Копия из серверной установки обычно старее игровых данных и падает с `Multiple declaration of function 'GetGame'`. |
| `serverConfig` | **Боевой** `serverDZ.cfg`. Расширение делает копию и форсит в ней `BattlEye=0`, `verifySignatures=0`, `forceSameBuild=0`, `allowFilePatching=1`; оригинал не трогается. Самодельный минимальный конфиг не годится — движок выключает сервер через 10 секунд. |
| `mission` | Относительный путь резолвится от папки **сервера**, а не диага. С неверным путём сервер поднимется без `init.c` миссии: `player connect will stay disabled`, нет экономики, игрок подключиться не может. |
| `port` | Игровой порт отладочного сервера; клиент подключается к нему же. Это не порт отладчика — тот задан движком. |
| `playerName` | Имя, под которым заходит отладочный клиент (`-name=`). |
| `profilesDir` | Профиль сервера. По умолчанию — `profiles/` рядом с exe сервера. |
| `clientProfilesDir` | Профиль клиента. По умолчанию — `Documents\DayZ`. |

Профиль — это логи и то, куда смотрит `$profile:` из скриптов, поэтому по умолчанию берутся
боевые профили: конфиги мода читаются оттуда же, откуда в обычной игре. Копируется только
`serverDZ.cfg` — в `builds/serverDZ.debug.cfg`, оригинал не трогается.

## Что доступно на останове

- Точки в своём коде, в зависимостях, в скриптах движка и в `init.c` миссии.
- Стек вызовов с настоящими файлами: пути переводятся из движковой формы PBO обратно в дисковую,
  включая регистр, — кадр не открывает вторую копию файла.
- **Variables**: `Locals` и `This`, вложенные объекты раскрываются. Значение показывается
  содержимым, а не адресом: `Param1<string> {param1='SCRIPT : …'}`. Если движок не прислал полей
  для `this`, группа так и подписана — вместо молча пустого списка.
- **Watch**-выражения, включая доступ к членам (`params.param1`).
- **Debug Console** исполняет **одиночный оператор** в контексте `Mission`, поэтому `GetGame()`
  доступен:

  ```c
  GetGame().GetMission().OnInit();
  ```

  Составной оператор (несколько выражений в строке) не исполняется вовсе, а классы модуля
  `5_Mission` по имени не видны — вызывать через базовый тип.

## Логи

**Run server** и **Run client** пишут каждый в свой канал вывода. Перед каждым запуском мод
пересобирается; если игра уже запущена, сборка пропускается — её PBO залочены.

`enforce.run.logLevel` — что попадает в основной канал:

| Значение | Что остаётся в канале |
| --- | --- |
| `errors` | только ошибки |
| `important` (по умолчанию) | ошибки, предупреждения и вехи — `Module: Mission`, подключение игрока, отсчёт выключения |
| `full` | весь поток |

Нетронутый поток всегда идёт в **Enforce Server (raw)** / **Enforce Client (raw)**, а в канал
печатается кликабельный путь к файлам лога на диске.

## Ограничения

**Стартовый код миссии первым проходом не поймать.** Игра подключается к отладчику строго после
инициализации миссии: `Module: Mission` проходит примерно на +17 с, подключение — на +18…19 с.
Точки в `OnInit` и в конструкторах модулей подтверждаются, но их исполнение уже позади.

Два обходных пути:

1. Дёрнуть заново из Debug Console — `GetGame().GetMission().OnInit();`. Цена: второй проход и
   повтор побочных эффектов.
2. Отложить стартовую работу — так ловится **первое и единственное** исполнение:

   ```c
   override void OnInit()
   {
       super.OnInit();
       GetGame().GetCallQueue(CALL_CATEGORY_SYSTEM).CallLater(MyDeferredInit, 15000, false);
   }

   void MyDeferredInit()   // точки здесь ловят первый проход
   {
       GetMyModule().Init();
   }
   ```

Всё, что исполняется после подключения, ловится штатно: `OnUpdate`, события, RPC, вход игрока
(`CreateCharacter`, `StartingEquipSetup` в `init.c` миссии).

Не тратьте время на: `-waitForDebugger` (ждёт **нативный** отладчик и вешает сервер),
`-donothing`, Workbench (тот же движок, раньше не подключается), `PlayMission()` (на сервере
пустышка), `AbortMission()` (уводит миссию в `MissionDummy`).

**Обфусцированные зависимости исключены** из карты путей: у них известен только API, номера строк
на диске не совпадают с реальным файлом. Точки в них остаются неподтверждёнными вместо останова
не в том месте, а при старте сессии консоль перечисляет такие моды поимённо.

## Команды

| Команда | Описание |
| --- | --- |
| `Enforce: Listen for DayZDiag (debug side)` | Держать порт стороны; `off` освобождает его |

| `Enforce: Run Client` | Запустить диаг клиентом |
| `Enforce: Stop Game and Debugging` | Остановить оба |
