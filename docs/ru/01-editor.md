# Код и редактор

[← К оглавлению](../../README.ru.md) · [English version](../en/01-editor.md)

Всё ниже работает от одного индекса: ваш код, зависимости из `load[]`, скрипты движка и все
слои `modded` в порядке загрузки.

## Автокомплит

- Члены того типа, который реально стоит слева от точки: цепочки вызовов, дженерики, `auto`,
  переменные `foreach`.
- У каждого пункта — класс-владелец и сколько модов его уже переопределяли.
- После имени enum — его значения, с числами и в порядке объявления.
- Члены за выключенным гардом скрыты (`enforce.conditionalMembers: dim` — показывать
  перечёркнутыми).

## Навигация и hover

- `F12` и hover резолвят по типу, а не по имени.
- В попапе: сигнатура, класс-владелец, мод и модуль, все слои `modded` и переопределения в
  наследниках.
- `super` ведёт туда же, куда пошёл бы движок: в слое `modded` — в предыдущий слой по порядку
  загрузки, в базовом классе — к родителю.
- У `this` и `super` тот же попап, что у имени типа.
- **Signature help** при наборе вызова: полная сигнатура с подсветкой активного параметра, а
  когда аргументы позволяют — сужение до одной перегрузки.
- Файлы движка и зависимостей открываются read-only (`enforce.readonlyExternal`).

## Инлайн-подсказки

| Настройка | Что показывает |
| --- | --- |
| `enforce.inlayHints.autoTypes` | выведенный тип для `auto` |
| `enforce.inlayHints.parameterNames` | имена параметров в вызовах |
| `enforce.inlayHints.parameterModifiers` | `out` / `inout` у аргументов |
| `enforce.inlayHints.truthiness` | что на самом деле проверяет не-bool условие |

```c
auto: eAIBase ai = eAIBase.Cast(from: g_Game.CreateObject(type: "eAI_SurvivorM_Mirek", pos: "1 1 1"));
if (!Class.CastTo(out to: data, from: params))
if (is null: !ai)
```

Там, где тип или перегрузку вывести нельзя, подсказки молчат. Убираются штатно —
`editor.inlayHints.enabled` (например, `offUnlessPressed` — показывать по `Ctrl+Alt`).

## Диагностика

На сохранении файл парсится и проверяется линтером и семантикой: ошибки разбора, необъявленные
методы и переменные (включая out-параметры), неизвестные типы, неверная арность,
конструирование класса с приватным конструктором и ещё около полусотни правил.

- Серьёзность соответствует движку: что движок прощает — предупреждение, что отвергает — ошибка.
- У каждого правила есть код, он виден в Problems. Перекрывается через `enforce.rules`:

  ```jsonc
  "enforce.rules": { "ternary-unsupported": "off", "undeclared-variable": "error" }
  ```

- Категории целиком переключаются настройками `enforce.parseDiagnostics` и
  `enforce.semanticDiagnostics` (`warning` / `error` / `off`).
- Имена, которые движок объявляет со стороны C++, в скриптах отсутствуют — перечислите их в
  секции `environments` манифеста, тогда они перестанут быть «необъявленными» и получат поиск,
  hover и переход к объявлению:

  ```jsonc
  "environments": { "DBT_OK": 0, "DBB_NONE": 0, "DMT_INFO": 1 }
  ```

Отдельно про индексацию: `x[k]` работает не только у `array` и `map` — у обычного класса
скобки раскрываются в его собственные `Get`/`Set`. Нет нужного метода — движок не соберёт
файл (`Undefined function 'X.Get'`), и это ловит правило `index-without-getset`. Для записи
`x[k] = v` одного `Get` мало, нужен `Set`.

Проверка всего проекта разом, а не пофайлово, — см. [предполёт](04-build.md#предполёт).

## Встроенные макросы

У препроцессора Enforce ровно два встроенных макроса — `__LINE__` и `__FILE__`, и оба
подставляются СТРОКОЙ: `int n = __LINE__;` движок не компилирует, `string s = __LINE__;`
компилирует. Анализатор их знает, автодополнение предлагает.

Наследия Arma (`__DATE__`, `__TIME__`, `__COUNTER__`, `__FUNCTION__`) в движке нет:
на такое имя компилятор отвечает «Can't find variable».

## Дефайны препроцессора

Дефайны собираются отовсюду, откуда их берёт движок:

| Источник | Пример |
| --- | --- |
| `#define` в скриптах | `#define EXPANSION_MODSTORAGE` |
| `defines[]` в `config.cpp` (`CfgMods`) | `defines[] = {"EXPANSIONMOD"};` |
| имя класса `CfgMods` | движок объявляет дефайн на каждый загруженный мод |
| `defines` в манифесте | то, чего не объявляет ни один исходник (C++-сторона движка, закрытые PBO) |
| `//#define` | объявлено и выключено автором |

Что видно в редакторе:

- блоки под выключенным гардом затемнены;
- hover на гарде говорит, включён он и откуда взялось значение;
- `F12` по дефайну ведёт к объявлению, `Shift+F12` перечисляет все `#ifdef`/`#ifndef`;
- гард, который нигде не объявлен, репортится (`enforce.unknownDefines`) — такой код не
  соберётся никогда. Команда **Enforce: Declare Unknown Defines in enforce.project.json**
  дописывает такие имена в манифест как `false`.

Приоритет: манифест > объявление в живом контексте > выключен.

### Типы, которых не будет

Если все объявления класса лежат под выключенным гардом, его использования затемняются
(`enforce.dimDeadTypes`) и помечаются (`enforce.deadTypeDiagnostics`) с указанием виноватого
гарда — это движковый `Unknown type`, показанный до сборки, а не после.

Репортится только разрешимый гард: явно `false` в манифесте или не объявленный нигде. Гарды,
которые движок объявляет со стороны C++, не трогаются.

## Форматтер

Форматирование документа или выделения — штатными командами VS Code. По умолчанию работает
встроенный форматтер, его умолчания сняты с реального корпуса: табы, скобки по Allman, пробел
после ключевых слов.

```jsonc
"enforce.formatting": {
  "useSpaces": false,
  "tabSize": 4,
  "allmanBraces": true,
  "spaceAfterKeyword": true,
  "astylePath": "",        // указать, чтобы форматировать через AStyle (при ошибке — встроенный)
  "astyleRcPath": "",
  "astyleArgs": []
}
```

## Подсветка

В расширении есть TextMate-грамматика и семантические токены: методы, классы, свойства,
параметры, переменные, члены enum и параметры типов раскрашиваются по данным индекса, а не по
догадке регулярки.

## Индекс

- Строится при активации, кэш — `%LOCALAPPDATA%/EnforceTools/cache`.
- Изменения в воркспейсе подхватываются сразу — вотчером и по фокусу окна.
- Изменения снаружи (движок, зависимости) ревалидируются каждые `enforce.autoRefreshSeconds`
  (по умолчанию 300, `0` — выключить).
- **Enforce: Rebuild Index** — полная переиндексация.

## Команды

| Команда | Описание |
| --- | --- |
| `Enforce: Rebuild Index` | Полная переиндексация |
| `Enforce: Show All Modifications (discovery)` | Все слои `modded` класса |
| `Enforce: Declare Unknown Defines in enforce.project.json` | Дописать неизвестные дефайны в манифест как `false` |
| `Enforce: Create Project File` | Создать `enforce.project.json` |

Полный список настроек — [Манифест и launch.json](06-manifest.md#настройки-vs-code).
