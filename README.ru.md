# Enforce Tools (DayZ)

[English version / Английская версия](README.md)

VS Code, который наконец понимает **DayZ Enforce Script** — твой мод, его зависимости и
скрипты движка вместе со слоями `modded`. Автокомплит, навигация, поиск ссылок, ошибки до
сборки и проверка настоящим движком по `F5`.

> ⚠️ **Бета.** Между релизами возможны ошибки и изменения — баг-репорты очень приветствуются.

![Панель references и попап класса](images/references-panel-class.png)

## Проблема

Из коробки VS Code видит EnScript просто текстом. Автокомплит предлагает всех однофамильцев
корпуса, «перейти к определению» уводит в чужой мод, а про опечатку узнаёшь только когда
сервер отказался стартовать — минут через пять и с ошибкой в файле, который ты не трогал.

Плагин вместо этого строит индекс всей картины: твой код, зависимости, скрипты движка
и каждый слой `modded` в порядке загрузки. Всё остальное — следствие.

## Что это даёт

### Автокомплит по настоящему типу

Не «все методы с таким именем», а члены того типа, который реально стоит слева от точки.
Цепочки вызовов, дженерики, `auto`, переменные `foreach`. У каждого пункта видно
класс-владелец и сколько модов уже его трогали.

![Автокомплит с владельцами](images/completion-owners.png)

После имени enum'а предлагаются его значения — с числами и в порядке объявления.

### Навигация, которая учитывает слои

Hover и `F12` резолвят по типу, а не по имени. В попапе — кликабельная сигнатура,
класс-владелец, мод и модуль, все слои `modded` и переопределения в наследниках: сразу
видно, кто ещё менял этот метод. `super` ведёт ровно туда, куда пошёл бы движок.

![Hover с дефинициями и override'ами](images/hover-definitions.png)

### Поиск ссылок в нормальной панели

`Shift+F12` открывает нижнюю панель в стиле Visual Studio: сверху декларации и слои, ниже —
использования, разложенные на вызовы, чтения, записи, конструкторы и колбэки. Фильтры по
колонкам, сортировка, сворачивание групп, закрепление результата в отдельную вкладку.
Даже десять тысяч строк не тормозят.

![Панель references для члена класса](images/references-panel-member.png)

Текстовые совпадения по умолчанию скрыты — одна кнопка в тулбаре возвращает их, когда они
действительно нужны. У значений enum'а свои счётчики ссылок, включая строковые литералы
из MVC-биндингов:

![References членов enum](images/enum-members.png)

### Дефайны: видно, что включено, что нет и что не соберётся

Половина DayZ-проекта живёт под `#ifdef`. Плагин собирает дефайны отовсюду, откуда они
вообще берутся — `#define` в скриптах, `defines[]` в `config.cpp`, имена модов и ручки,
которые автор оставил закомментированными, — и показывает результат:

- мёртвые блоки `#ifdef` затемняются, и ты не читаешь код, которого нет;
- hover на гарде говорит, включён он или нет и откуда это значение;
- `F12` ведёт к объявлению, `Shift+F12` показывает все места, где гард используется;
- гард, который нигде не объявлен, подсвечивается как ошибка — такой код не соберётся никогда.

С типами то же самое: если все объявления класса лежат под выключенной ручкой, его

редакторе, а не в конце сборки, и с указанием виноватой ручки.

### Ошибки ловятся до сборки

На сохранении файл парсится, проверяется линтером и семантикой: необъявленные методы и
функции, неизвестные типы, неверное число аргументов. Серьёзность подогнана под движок:
что он прощает — предупреждение, что отвергает — ошибка.

![Диагностика](images/diagnostics.png)

По желанию та же проверка прогоняется по всему проекту прямо перед сборкой — чтобы не
тратить пятиминутный круг через сервер на опечатку. Останавливает только на том, что движок
не примет, и в диалоге всегда есть **Build anyway**.

<!-- TODO скриншот: диалог предполёта -->

### Одна клавиша — собрать и спросить движок

`F5` пакует мод в PBO (без AddonBuilder и прочих тулов) и гоняет компиляцию headless
DayZ Server — вердикт настоящего компилятора секунд за десять. Первопричины отделены от
каскада, который за ними тянется, и каждая ошибка замаплена обратно на твой файл в панели
Problems. `Ctrl+Shift+B` — только собрать PBO.

Упаковщик кладёт в PBO **только скрипты** — этого достаточно, чтобы движок скомпилировал
код и вынес вердикт. Полноценная упаковка мода, с ассетами, появится позже.

![Проверка движком](images/build-check.png)

Лог сборки раскрашен, а каждый путь в нём кликабельный — включая `config.cpp` пропущенного
модуля, по которому видно, почему его пропустили. Повторный `F5` после неудачи просто
работает: плагин дожидается, пока предыдущий сервер закроется.

### Мелочи, которые складываются

- **Inlay-подсказки для `auto`** — выведенный тип прямо в строке, и ничего, если тип вывести
  не удалось.
- **Signature help** с подсветкой активного параметра по мере ввода аргументов.
- **Форматтер** для файла или выделения (или укажи путь к своему AStyle).
- **CodeLens и семантические цвета** — «N references» / «N layers» над декларациями.
- **Исходники движка и зависимостей открываются read-only** — случайно не испортишь.

## Как начать

### 1. Распакованные скрипты игры

Плагин читает ванильные скрипты как обычные исходники, поэтому они нужны на диске
распакованными. Обычный путь — **DayZ Tools** → *Extract Game Data*: он монтирует Work Drive
как `P:` и раскладывает скрипты в `P:\scripts` (папки `1_Core` … `5_Mission`). Подойдёт и
любая другая локальная копия — просто укажи в конфиге, где она лежит.

С модами-зависимостями так же: нужны их **исходники** или распакованные аддоны. Подключить
`.pbo` напрямую пока нельзя — это в планах. Без распакованных зависимостей плагин работать
будет, но их классов не увидит: ни автокомплита, ни переходов по ним.

### 2. `enforce.project.json` в корне проекта

Файл кладётся рядом с `config.cpp` твоего мода. Минимальный работает буквально такой:

```jsonc
{}
```

Но лучше сразу начать с такого — ванильные скрипты, имя мода, куда собирать и где стоит
DayZ Server для отладки:

```jsonc
{
  "engine": "P:/scripts",
  "build": {
    "modName": "@MyMod",
    "outDir": "./builds",
    "serverExe": "D:/Steam/steamapps/common/DayZServer/DayZServer_x64.exe",
    "serverCwd": "D:/Steam/steamapps/common/DayZServer"
  }
}
```

Зависимости добавишь, когда понадобятся, — ключ `load[]`, см. справочник ниже. Ключи в
манифесте подсказываются прямо при наборе, а опечатка подчёркивается сразу, а не молча
перестаёт работать.

### 3. Запуск по `F5`

Создай `.vscode/launch.json` в корне воркспейса:

```jsonc
{
  "version": "0.2.0",
  "configurations": [
    { "type": "enforce", "request": "launch", "name": "Enforce: Build & Check" }
  ]
}
```

VS Code предложит её и сам: *Run and Debug* → *create a launch.json file* →
**Enforce Build & Check**. Больше ничего не требуется — по `F5` плагин соберёт PBO и
прогонит проверку движком.

### Нет DayZ Server под рукой?

Тогда проверяй код нашим анализатором — включи `preflight`:

```jsonc
{
  "engine": "P:/scripts",
  "build": { "preflight": true }
}
```

По `F5` плагин сначала прогонит проверку по всему проекту и покажет ошибки, а потом упрётся
в отсутствующий сервер и честно об этом скажет. Ни запакованные зависимости (`build.deps`),
ни путь к серверу для такой проверки не нужны — а вот исходники зависимостей в `load[]`
указать стоит, иначе резолв будет неполным. Так дольше: проверка не такая полная, как
вердикт настоящего компилятора, и часть ошибок вскроется позже, уже на сервере. Зато
начать можно без игры.

## Команды

| Команда | Описание |
| --- | --- |
| `Enforce: Find All References (Panel)` | Панель references для символа под курсором (`Shift+F12`) |
| `Enforce: Build Check (Engine Compile)` | PBO + headless-компиляция движком (`F5`) |
| `Enforce: Rebuild Index` | Принудительная полная переиндексация |
| `Enforce: Show All Modifications (discovery)` | Все modded-слои класса |
| `Enforce: Declare Unknown Defines in enforce.project.json` | Дописать все неизвестные дефайны в манифест как `false` |

## Настройки

| Настройка | Дефолт | Описание |
| --- | --- | --- |
| `enforce.workDrive` | `P:` | Work Drive с распакованными скриптами движка |
| `enforce.parseDiagnostics` | `warning` | Диагностика парсинга: warning / error / off |
| `enforce.semanticDiagnostics` | `warning` | Семантическая диагностика: warning / error / off |
| `enforce.unknownDefines` | `warning` | Гарды, дефайн которых нигде не объявлен |
| `enforce.deadTypeDiagnostics` | `warning` | Типы, объявленные только под выключенной ручкой |
| `enforce.dimDeadTypes` | `true` | Затемнять такие типы в редакторе |
| `enforce.conditionalMembers` | `hide` | Члены за ложным гардом: hide / dim |
| `enforce.codeLensReferences` | `true` | «N references» над декларациями |
| `enforce.inlayHints.autoTypes` | `true` | Показывать выведенный тип для `auto` |
| `enforce.references.includeTextMatches` | `false` | Показывать текстовые совпадения в панели по умолчанию |
| `enforce.preflight` | `false` | Проверять проект перед запуском сборки |
| `enforce.readonlyExternal` | `true` | Открывать исходники движка и зависимостей read-only |
| `enforce.autoRefreshSeconds` | `300` | Подхватывать изменения вне воркспейса (0 = выкл) |
| `enforce.formatting` | `{}` | Опции форматтера (отступы, скобки, путь к AStyle) |
| `enforce.build` | — | Дефолты сборки, перекрываются `build{}` в манифесте |

## Справочник `enforce.project.json`

Все ключи необязательные. Максимально заполненный пример:

```jsonc
{
  // ===== ЧТО ИНДЕКСИРУЕТСЯ ==================================================
  // Отсюда плагин узнаёт, какой код он читает: от этого зависят автокомплит,
  // переходы, ссылки и диагностика.

  // Распакованные скрипты базовой игры (папка с 1_Core … 5_Mission).
  // Убери ключ — возьмётся <workDrive>/scripts.
  "engine": "E:/DayZ/WorkDrive/scripts",

  // Моды-зависимости — ИСХОДНИКИ или распакованные аддоны, в порядке загрузки
  // (.pbo пока нельзя). Папка с несколькими модами (как DayZ-Expansion-Scripts)
  // разворачивается в слои автоматически.
  "load": [
    // github.com/Arkensor/DayZ-CommunityFramework
    { "name": "CF",        "path": "D:/mods/DayZ-CommunityFramework/JM/CF", "role": "dependency" },
    // github.com/salutesh/DayZ-Expansion-Scripts
    { "name": "Expansion", "path": "D:/mods/DayZ-Expansion-Scripts", "role": "dependency" }
  ],

  // Твой собственный код. Не нужен, если исходники лежат рядом с манифестом.
  "project": [
    { "name": "MyMod", "path": "./src" }
  ],

  // ===== ЧТО СЧИТАТЬ ВКЛЮЧЁННЫМ =============================================
  // Управляет #ifdef: что затемняется, какие члены видны в автокомплите,
  // какие типы помечены как несобираемые.

  // Дефайны, которых не видно из исходников: те, что движок добавляет сам, и те,
  // что приходят из закрытых PBO. Всё объявленное в твоём коде и зависимостях
  // подхватывается автоматически — значение отсюда просто важнее.
  // Проверка движком печатает его реальный список и предлагает импортировать.
  "defines": {
    "PLATFORM_WINDOWS": true,
    "SERVER": true,
    "DZ_Expansion_Core": true,
    "DIAG": false
  },

  // ===== ПОИСК ССЫЛОК =======================================================
  // Насколько широко ищем использования и что показываем в панели.

  // Разрешить ссылкам, CodeLens и Shift+F12 работать и на файлах движка и
  // зависимостей. У популярных типов движка бывают тысячи использований.
  "externalReferences": true,

  "references": {
    // Показывать текстовые совпадения в панели по умолчанию (кнопка в панели есть всегда).
    "includeTextMatches": false
  },

  // ===== СБОРКА И ПРОВЕРКА ДВИЖКОМ (F5) =====================================
  // Всё, что нужно, чтобы упаковать мод в PBO и скормить его headless-серверу.
  // Если проверка движком не нужна, хватит одного preflight.

  "build": {
    // Проверить проект нашим анализатором перед запуском движка.
    "preflight": true,

    "modName": "@MyMod",            // имя выходной папки
    "outDir": "./builds",           // артефакты: <outDir>/<modName>/addons/*.pbo

    // Запакованные моды-зависимости для -mod=, в порядке загрузки.
    "deps": [
      "D:/Steam/steamapps/common/DayZ/!Workshop/@CF",
      "D:/Steam/steamapps/common/DayZ/!Workshop/@DayZ-Expansion-Core"
    ],

    // Где лежит DayZ Server. Убери оба ключа — найдётся автоматически по Steam.
    // Нужен DayZServer_x64.exe; DayZDiag требует запущенный клиент Steam.
    "serverExe": "E:/Games/SteamLibrary/steamapps/common/DayZServer/DayZServer_x64.exe",
    "serverCwd": "E:/Games/SteamLibrary/steamapps/common/DayZServer",

    "mission": "mpmissions/dayzOffline.chernarusplus",
    "timeoutSec": 240
  }
}
```

В путях работают и `/`, и `\\`. Префикс PBO не настраивается — он берётся из `config.cpp`
каждого модуля, а проект из нескольких модулей пакуется в отдельный PBO на каждый модуль.
