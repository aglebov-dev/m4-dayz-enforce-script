# Enforce Tools (DayZ)

[English version / Английская версия](README.md)

**Экспериментальная IDE** для **DayZ Enforce Script** (EnScript) в VS Code — на базе
modded-aware индекса проекта и in-process WASM-парсера. Никаких внешних тулов и процессов:
открой свой мод и получи автокомплит, навигацию, поиск ссылок, диагностику и проверку
компиляции настоящим движком.

> ⚠️ **Бета-версия** — разработка активно ведётся. Между релизами возможны ошибки и
> изменения поведения; фидбек и баг-репорты очень приветствуются.

![Панель references и попап класса](images/references-panel-class.png)

## Возможности

### Modded-aware индекс

Понимает слои `modded class`, порядок загрузки, наследование (extends-DAG), typedef'ы и
дженерики по твоему моду, его зависимостям и скриптам движка. Холодный старт на большом
корпусе (движок + Expansion + CF, ~5000 файлов) — несколько секунд; тёплый старт из
кэша — ~200 мс.

### Автокомплит по типам

Члены *реально выведенного* типа получателя — цепочки вызовов (`GetGame().CreateObject().`),
дженерики (`array<MyCfg>` → один `Insert`, а не 38 однофамильцев), вывод `auto`, переменные
`foreach`. У каждого пункта показан класс-владелец и число modded-слоёв; члены, скрытые
неактивными `#ifdef`-гардами, обрезаются (или показываются зачёркнутыми).

![Автокомплит с владельцами](images/completion-owners.png)

### Hover / Go to Definition

Резолв семантический — по типу получателя, а не по имени. Попапы показывают раскрашенные
**кликабельные** сигнатуры (каждый тип и имя — ссылка), класс-владелец, скрипт-модуль и
мод, modded-слои, переопределения в наследниках и резолв `super` по реальной цепочке
modded-слоёв.

![Hover с дефинициями и override'ами](images/hover-definitions.png)

### Панель References

`Shift+F12` открывает нижнюю панель в стиле Visual Studio: сверху группа деклараций и
слоёв (base / modded layer / override / inherited), ниже — использования с классификацией
call / read / write / constructor / text-match, фильтры по колонкам, ресайз колонок,
колонки мода / модуля / содержащего метода, сворачивание групп, закрепление результата в
отдельную вкладку (📌) и виртуализированный рендер для 10k+ строк. Виртуальный диспатч
отслеживается: вызов через ссылку базового класса помечается на override'е знаком `?`.

![Панель references для члена класса](images/references-panel-member.png)

Члены enum'ов — полноценные символы: у каждого значения свой счётчик ссылок, включая
строковые литералы MVC-биндингов (text-match):

![References членов enum](images/enum-members.png)

### CodeLens и семантическая подсветка

«N references» / «N layers» над декларациями, семантические цвета из индекса и затемнение
мёртвых `#ifdef`-регионов по дефайнам проекта.

![CodeLens и подсветка](images/codelens-highlighting.png)

References работают и на исходниках движка/зависимостей (опциональный флаг
`externalReferences` — скан всего корпуса):

![References на исходниках движка](images/engine-references.png)

### Signature Help

Перегрузки с подсветкой активного параметра по мере ввода:

![Signature help](images/signature-help.png)

![Signature help, активный параметр](images/signature-help-params.png)

### Диагностика на сохранении

Ошибки парсинга откалиброваны под то, что движок реально отвергает: тернарный оператор —
ошибка, пропущенная `;` — только warning (движок её прощает). Семантический проход
репортит необъявленные методы/функции, неизвестные типы, арность вызовов и лишние
аргументы дженериков (движок их молча игнорирует — известная ванильная ловушка).

![Диагностика](images/diagnostics.png)

### Проверка движком

`F5` пакует мод в PBO (свой паковщик, без AddonBuilder) и гоняет компиляцию headless
DayZ Server: вердикт **настоящего** компилятора за ~10 с. Первопричины отделены от
каскадных ошибок, всё замаплено обратно на твои исходники в панели Problems, плюс
печатается реальный список дефайнов движка (можно импортировать в манифест).
`Ctrl+Shift+B` — только собрать PBO.

![Проверка движком](images/build-check.png)

## Требования

- **DayZ Tools** со смонтированным Work Drive (`P:`) или любая локальная копия
  распакованных скриптов движка (`scripts/1_Core` … `5_Mission`).
- Манифест `enforce.project.json` в корне воркспейса (см. ниже).
- Для проверки движком: локально установленный DayZ Server (автодетект по путям Steam
  или явное указание).

## Быстрый старт

Минимальный `enforce.project.json` (движок на `P:`, без зависимостей):

```jsonc
{}
```

Да, пустой объект работает: движок берётся из `P:/scripts`, корень мода находится по
`config.cpp` рядом с манифестом. Зависимости добавляются по мере надобности — см. полный
справочник ниже.

## Команды

| Команда | Описание |
| --- | --- |
| `Enforce: Find All References (Panel)` | Панель references для символа под курсором (`Shift+F12`) |
| `Enforce: Rebuild Index` | Принудительная полная переиндексация (сброс дискового кэша) |
| `Enforce: Show All Modifications (discovery)` | Все modded-слои класса |
| `Enforce: Build Check (Engine Compile)` | PBO + headless-компиляция движком (`F5`) |

## Настройки

| Настройка | Дефолт | Описание |
| --- | --- | --- |
| `enforce.workDrive` | `P:` | Work Drive DayZ Tools с распакованными скриптами движка |
| `enforce.parseDiagnostics` | `warning` | Диагностика парсинга: warning / error / off |
| `enforce.semanticDiagnostics` | `warning` | Семантическая диагностика: warning / error / off |
| `enforce.conditionalMembers` | `hide` | Члены с ложным `#ifdef`-гардом: hide / dim |
| `enforce.codeLensReferences` | `true` | CodeLens «N references» над декларациями |
| `enforce.readonlyExternal` | `true` | Открывать исходники движка/зависимостей read-only |
| `enforce.autoRefreshSeconds` | `300` | Фоновая ревалидация внешних корней (0 = выкл) |
| `enforce.build` | — | Дефолты билд-гейта (перекрываются `build{}` манифеста) |

## Полный справочник конфигурации

Максимально заполненный `enforce.project.json` — кастомное расположение скриптов движка,
кастомный DayZ Server, зависимости, явные корни проекта, дефайны и билд-гейт:

```jsonc
{
  // ---- скрипты движка -------------------------------------------------------
  // Кастомное расположение распакованных скриптов базовой игры (папка, в которой
  // лежат 1_Core, 2_GameLib, 3_Game, 4_World, 5_Mission).
  // Убери ключ совсем — возьмётся дефолт: <workDrive>/scripts (P:/scripts).
  // ${WORKDRIVE} разворачивается из настройки VS Code enforce.workDrive.
  "engine": "E:/DayZ/WorkDrive/scripts",
  // "engine": "${WORKDRIVE}/scripts",        // эквивалент дефолта

  // ---- дефайны препроцессора ------------------------------------------------
  // Управляют вычислением #ifdef-гардов: фильтрация членов в автокомплите,
  // затемнение мёртвых регионов, подавление диагностики. Проверка движком
  // печатает РЕАЛЬНЫЙ список дефайнов твоего движка («engine defines: ...»
  // в выводе) — скопируй его сюда.
  // true = определён, false = явно не определён. Дефайн, которого здесь НЕТ,
  // считается неопределённым (строго, как препроцессор движка).
  "defines": {
    "PLATFORM_WINDOWS": true,
    "SERVER": true,
    "RELEASE": true,
    "DAYZ_1_29": true,
    "JM_CommunityFramework": true,
    "DabsFramework": true,
    "DZ_Expansion_Core": true,
    "DZ_Expansion_AI": true,
    "DIAG": false
  },

  // ---- моды-зависимости (исходники скриптов, в порядке загрузки) ------------
  // Каждая запись — корень с ИСХОДНИКАМИ мода (не запакованные PBO). Корень с
  // несколькими config.cpp-модами (как DayZ-Expansion-Scripts) автоматически
  // разворачивается в помодовые слои. Относительные пути — от папки манифеста.
  "load": [
    { "name": "CF",        "path": "D:/mods/DayZ-CommunityFramework/JM/CF", "role": "dependency" },
    { "name": "DABS",      "path": "D:/mods/DayZ-Dabs-Framework/DabsFramework", "role": "dependency" },
    { "name": "Expansion", "path": "D:/mods/DayZ-Expansion-Scripts", "role": "dependency" }
  ],

  // ---- корни проекта (твой код) ---------------------------------------------
  // Необязательно. Нет ключа → корень проекта = папка манифеста, моды находятся
  // по config.cpp. Указывай явно, когда исходники лежат в другом месте:
  "project": [
    { "name": "MyMod", "path": "./src" }
  ],

  // ---- скоуп references -----------------------------------------------------
  // true → CodeLens / hover / Shift+F12 работают и на файлах движка/зависимостей
  // (сканы по всему корпусу; у популярных типов движка бывают тысячи использований).
  // false/нет ключа → references сканируют только файлы проекта (дёшево).
  "externalReferences": true,

  // ---- билд-гейт движка (F5) ------------------------------------------------
  "build": {
    // упаковка PBO
    "modName": "@MyMod",            // имя выходной папки мода (дефолт: @<папка манифеста>)
    "prefix": "MyMod",              // префикс PBO; ОБЯЗАН совпадать с CfgMods files[] ("MyMod/Scripts/...")
    "outDir": "./builds",           // артефакт: <outDir>/<modName>/addons/<prefix>.pbo

    // запакованные моды-зависимости для -mod= (воркшоп или локальные @папки, порядок загрузки)
    "deps": [
      "D:/Steam/steamapps/common/DayZ/!Workshop/@CF",
      "D:/Steam/steamapps/common/DayZ/!Workshop/@Dabs Framework",
      "D:/Steam/steamapps/common/DayZ/!Workshop/@DayZ-Expansion-Core",
      "D:/Steam/steamapps/common/DayZ/!Workshop/@DayZ-Expansion-AI"
    ],

    // Кастомное расположение DayZ Server. Убери оба ключа → автодетект по
    // стандартным путям Steam. Нужен именно DayZServer_x64.exe (standalone) —
    // DayZDiag требует запущенный Steam-клиент и не используется.
    "serverExe": "E:/Games/SteamLibrary/steamapps/common/DayZServer/DayZServer_x64.exe",
    "serverCwd": "E:/Games/SteamLibrary/steamapps/common/DayZServer",

    // Миссия для прогона компиляции (относительно serverCwd или абсолютный путь).
    "mission": "mpmissions/dayzOffline.chernarusplus",

    // Жёсткий таймаут одного прогона, секунды.
    "timeoutSec": 240
  }
}
```

Примечания:

- **Пути Windows**: в манифесте работают и `/`, и `\\`; движку бэкслеши подставляются
  автоматически.
- `build{}` в манифесте перекрывает настройку VS Code `enforce.build` поключево.
- Вердикт компиляции выдаёт настоящий бинарь движка — ровно то, что скажут клиенты и
  серверы игроков.
