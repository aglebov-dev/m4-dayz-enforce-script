## Требования

- VS Code 1.85 или новее.
- Распакованные скрипты движка (**DayZ Tools** → *Extract Game Data* или любая локальная копия).
- Windows для сборки и отладки — они запускают `DayZServer_x64.exe` и `DayZDiag_x64.exe`.

## Быстрый старт

1. Распакуйте скрипты движка (`1_Core` … `5_Mission`).
2. Создайте `enforce.project.json` рядом с `config.cpp` вашего мода — команда
   **Enforce: Create Project File**:

   ```jsonc
   {
     "engine": "P:/scripts",
     "build": {
       "modName": "@MyMod",
       "outDir": "./builds",
       "serverExe": "D:/Steam/steamapps/common/DayZServer/DayZServer_x64.exe"
     }
   }
   ```

3. Добавьте `.vscode/launch.json` и нажмите `F5` — соберётся PBO (только скрипты) и выполнится прогон через движок игры:

   ```jsonc
   {
     "version": "0.2.0",
     "configurations": [
       { "type": "enforce", "request": "launch", "name": "Enforce: Build & Check" }
     ]
   }
   ```

Подробности — [Манифест и launch.json](docs/ru/06-manifest.md).

## Чужие моды

**Распаковка `.pbo`, разбор бинаризованного конфига и восстановление обфусцированного кода могут
нарушать ограничения, наложенные автором мода на свою работу.** Расширение даёт техническую
возможность — ответственность за её применение целиком на вас. Добавляя чужой мод в
`enforce.project.json`, вы подтверждаете, что вправе так поступать.

Цель — разрабатывать **своё**, когда чужой мод подключён как зависимость: нужен его публичный
API и ничего сверх того. Обфусцированные моды распоковываются **только как сигнатуры**:
заголовки классов, сигнатуры методов, типы полей. Тела методов не извлекаются.
